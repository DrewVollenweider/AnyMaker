## Control parts that avoid unnecessary microcontrollers

These rules are verified in the current installed descriptions. They were not retested through gameplay in this session.

| Definition | Documented behavior | Design consequence |
|---|---|---|
| `button_push`, `button_push_round` | Momentary; mechanical output 1 while held; boolean `is_pressed` output | A button is not a latch. |
| `switch`, `toggle_switch` | Each press toggles a latching mechanical output between 0 and 1 | Use a switch for a simple persistent on/off command. |
| `emergency_stop_button_a`, `emergency_stop_button_b` | **Momentary**, despite their appearance/name | Do not infer a persistent emergency-stop latch from the model. |
| `mechanical_junction_toggle` | Output toggles on each rise above 0.75; input must fall below 0.25 before another toggle | A native mechanical toggle may replace a scripted button latch. |
| `mechanical_junctions_set_reset` | Input A rising above 0.75 sets output to 1; B rising above 0.75 resets to 0 | Separate set/reset control exists; preserve the unusual plural `junctions` ID. Simultaneous-input priority remains unknown. |
| `mechanical_junction_max` / `min` | Larger / smaller of A and B | Combine brake or limit commands using the actual native operation. |
| `mechanical_junction_invert` / `abs` | Negative / absolute value of input | These handle simple sign/range conversion without a controller. |
| `mechanical_junction_offset` / `scale` / `add` | Add offset / multiply scale / add A and B; outputs limited to −1…1 | Account for clamping rather than assuming arbitrary signal magnitude. |
| `electric_relay` | Fitted electric ports join while on; mechanical activation on above 0.75, off below 0.25 | Relay is a power-network switch with distinct activation thresholds; it is not a proportional motor controller. |
| `gear_stick` | 2–10 gears; mechanical signal is gear divided by count | Mechanical fraction differs from integer data channel `throttle`; `throttle` and `gear_count` are `type_s32_output`. |

The steering-wheel pedal rule supplied by the user remains **digital on/off**. Floating-point 0–1 descriptors are channel ranges, not evidence of proportional pedal travel. A digital right pedal multiplied by 0.25 gives released/pressed requests of 0/0.25.

## Saved examples and native format facts

The refresh indexed **34 local `.data` creations** and **12 embedded script fields**, plus `scripts/buttontoggle.txt`. See creation index (local evidence not uploaded) and [saved script](../toolset/output/research-20261014/saved-scripts.json). These are user/community/generated files of mixed provenance. Presence on disk does not certify game acceptance or operation.

* **Mounting grids are not physical bodies.** `torquereverse.data` contains one vehicle (207) with two grids, including `origin=[28,10,0]`, `dir=[3,1,0]`. `engine.data` likewise contains one vehicle (326) with two grids. `trailerwithwinch.data` contains four vehicles with seven grids. The arrays make the distinction explicit. Component positions in an inclined grid cannot be plotted directly as body positions.
* **Interfaces can pair inside one body.** Torque interfaces 121↔124, 122↔123 and 135↔136 in `torquereverse.data` all point to vehicle 207. Do not enforce cross-body-only interface links based on an assumption about their intended use. The saved references establish pairings; torque delivery is not measured.
* **Hydraulic cylinder attachment is stored on the components.** In `hydraulicsnew.data`, vehicle 206 connector 2 points to vehicle 205 base 8, target `connected_node_index=2`; base 8 points back to connector 2, target index 0. The base additionally stores `length_max=10`, `extension_factor=1.0` and `hydraulic_cylinder.content_a/content_b`. Target node indexes are not the source connector's node indexes. Preserve fluid state and pair references when cloning. Pipe links remain a separate system; no invented `hydraulic_links` array is needed for this observed pair.
* **Controller variable state accompanies script text.** Controller 140 in `torquereverse.data` stores `global_private` entries: DIR as `{"_type":"f64","data_value":1.0}` and RELEASED as `{"_type":"bool","type":"type_bool","data_value":true}`. The trailer version stores DIR = −1.0. A script-only copy can lose saved state; initialization/reload behavior still requires testing.
* **The direction script uses a release guard.** `if (out DIRSWITCH.is_pressed && var RELEASED)` flips DIR; RELEASED is then assigned the inverse of the button state. This is static script logic that avoids toggling continuously while held. The script writes complementary 0/1 commands to `Right.input` and `Left.input`; these are commands rather than direct wheel torque.
* **The installed electric test cart has evolved.** Its saved controller now references `DriveSelect.throttle`, chooses direction at integer values 0 and 2, requests 0.5 rps and caps right-pedal power request at 0.25. Its selector has `gear_count=2`, `throttle=1`, and a `PedalRelay` is present. The earlier forward-only README is stale relative to these saved fields. This session did not prove the cart drives or its data network resolves every alias.

Its [native-grid research](https://github.com/DrewVollenweider/AnyMaker/blob/main/doc/06_REVERSE_ENGINEERING.md) reports a column-major native component matrix and a mounting transform with local Y along `normalize(dir)`, local X along `normalize(dir × up)`, and local Z along X×Y; up is Y except for parallel-Y directions, where it is Z. Non-base grid translation includes `origin + 0.5*sign(dir) + 0.5*normalize(dir)`. These are useful **prior-version static findings**, not newly certified v0.1.25 behavior. The repository's editor-specific X reflection must not be blindly applied to native-to-native tools.

## How future work should use this

Read this note and the older knowledge note before generating builds. Inspect actual definitions and saved examples for the requested component. Prefer native switch/junction logic where it meets the request. Distinguish mounting grids, rigid bodies, torque interfaces and data/control paths. Preserve unknown fields and controller state. Keep test results distinct from saved-file evidence and repository claims.

The reusable `toolset/research_install.py` refreshes version comparisons, source hashes, interfaces and creation/script indexes into a new output directory without overwriting prior research. The existing offline suite passed **26 tests** this session. Source hashes remained unchanged during research; no game files or user creations were edited. Complete grid/body projection, spatial mating and runtime operation remain future validation work.
