## What is now established

The convex-hull mass coefficient is a **signed volume integral**, rather than an unexplained cached scalar. The constructor calculates the hull centre and volume, integrates second moments about that centre, then caches the resulting inertia. The mass-properties method multiplies that volume and tensor by the shape's density.

This closes the selected hull **mass integration stage**. It does not finish the point-cloud hull generator, every degeneracy/error path, collision support/margin behavior, or creation-file geometry reconstruction. The new helper therefore takes an explicit closed boundary, with supplied vertices and outward-oriented face loops.

## Volume and centre

Actual hull table `0x54f338` has centre accessor slot `+0x10 -> 0x214070` and mass-properties slot `+0x38 -> 0x2344e0`. The accessor copies the cached centre at object offset `0x30`. The constructor `0x2328c0` passes that field and its cached volume field `0x104` to `0x2bd890`.

The complete reviewed volume helper spans five adjacent PE ranges, selected together as `0x2bd890:0x2bda5e`. Its reference point q is the mean of the per-face stored vectors at face offset `0x10`; the full construction of those face vectors is not established here. Each polygon face is triangulated as a fan. For each triangle with vertices a/b/c:

```text
D = dot(a-q, cross(b-q, c-q))
S = sum(D)
V = S/6
C = sum(D*(a+b+c+q))/(4*S)
```

The ordinary centroid division is used only when **S > 1.1920928955078125e-7**, the exact f32 constant. Otherwise the cached centre becomes q. Volume is still divided by six; this selected helper does not clamp it to a minimum. This is a centre-computation branch, **not a proven minimum valid hull volume or placement rule**.

For nondegenerate closed boundaries the reference point cancels mathematically. The helper tool uses the mean of supplied vertices as its reference, rather than duplicating the still-unclosed native face-vector construction. Native f32 rounding and small-volume behavior can therefore differ.

## Centred inertia

The constructor subtracts the computed centre from the face vertices. For each centred triangle, let A be the matrix whose columns are a/b/c, and let D be their scalar triple product. Its second-moment accumulation is equivalent to:

```text
B = [[1/60,  1/120, 1/120],
     [1/120, 1/60,  1/120],
     [1/120, 1/120, 1/60 ]]

J = sum(D * A * B * transpose(A))
I = trace(J)*identity - J
```

These coefficients are compiled f32 values: approximately **0.01666666753590107** and **0.008333333767950535**. The constructor stores this unit-density tensor at object offset `0x40`; `0x2344e0` scales it and the volume by the density at `0x28`. Selected arithmetic therefore explains off-diagonal products of inertia as well as the diagonal terms.

All 1,382 approximate C lines of the constructor were read in this continuation. The mass/centre integration is specifically traced; later face storage, adjacency and radius handling are observed but are not presented as a complete native geometric-equivalence proof. The mass fields are computed before those later radius adjustments.

## Consequences for plates and edges

### Eligible planar plate hulls

The [previously traced server builder](PLATE-SURFACES-20261021.md) supplies each eligible plate node twice, displaced along its unit normal by **0.08 * 0.35 = 0.028 m** and **0.08 * 0.45 = 0.036 m**. For an ordinary planar convex loop whose native hull retains that slab, its ideal volume is:

```text
V = polygon_area * 0.008
mass = V * 400 = polygon_area * 3.2
```

Thus a one-square-metre slab contributes approximately **3.2 native mass units**. A 0.8 by 0.4 m example contributes approximately **1.024**, with its centre 0.032 m along the normal from the node plane. The helper tests that explicit slab against analytic geometry.

This is a source-derived calculation for those hull inputs, not an in-game measurement or a universal plate-mass promise. Native f32 coordinate conversion, hull generation/degeneracy, eligibility and separate entries matter. Visible plate thickness is different, as documented in the preceding surface research. Opposed skins can produce separate compound contributions; no union subtraction is added by the reviewed compound mass method.

### Edge capsule dimensions

The selected `server_scene.vehicle.build_physics_shape` path constructs an edge capsule with:

```text
radius = width * (0.5 - 0.05)
cylinder_length = distance(node0_position, node1_position)
width = 0.08 normally
width = 0.24 when edge size value is 1
density argument = G_VEHICLE_EDGE_DENSITY = 1000
```

The radii are therefore **0.036 m** and **0.108 m**. Cylinder length is the node-position distance; this call does not subtract end-cap radii. The capsule's local Y axis is oriented along the edge and its transform uses the endpoint midpoint.

A separate temporary is multiplied by **9** in the size-1 branch. The selected assembly proves that the capsule call's fifth argument is the global edge-density pointer, rather than that temporary. This records the actual argument flow; it is not labeled a gameplay bug.

Using the [verified capsule formula](MASS-PROPERTIES-20261021.md), a 1 m cylinder length gives approximately **4.267** native mass units at radius 0.036 and **41.920** at radius 0.108, both at density 1000. These are model calculations with compiled constants, not exact native f32 outputs. Capsule end caps and overlapping compound entries explain why simply multiplying visible beam cross-section by length is insufficient.

## Tools and checks

New [polyhedral_mass.py](../../../scripts/research/polyhedral_mass.py) 1.0.0 exposes `surface_mass_properties(vertices, faces, density)`, returning mass, centre and the full COM inertia tensor. It checks finite coordinates, face indices, opposite boundary-edge pairs and a positive determinant sum above the native centre-fallback threshold. These are scoped model guards, not complete convexity, manifold, self-intersection or native hull-validity certification.

[mass_properties.py](../../../scripts/research/mass_properties.py) is now **1.1.0**. `TensorMassProperties` lets `combine` preserve supplied off-diagonal terms, rotate the full tensor and add displacement contributions. Child COM coordinates remain explicit; the tool does not infer native serialization transforms.

For example, with explicit vertices and faces already supplied:

```python
from mass_properties import Child, TensorMassProperties, combine
from polyhedral_mass import surface_mass_properties

hull = surface_mass_properties(vertices, faces, density=400)
child = Child(TensorMassProperties(hull.mass, hull.inertia), center=hull.center)
assembly = combine([child])
```
